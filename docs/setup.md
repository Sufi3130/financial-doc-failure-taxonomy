# Setup

The core stack runs on a laptop CPU with no GPU. Developed and tested on
**Windows 11 with Python 3.12.6**; the Linux and macOS steps below follow the
same shape and use the same CPU wheels, but have not been separately tested.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install -r requirements-later.txt   # optional: scikit-learn, Streamlit (M3+)
```

## Platform notes

### All platforms

- **Use a python.org CPython build** (3.12 recommended), or a standard distro /
  Homebrew Python. MSYS2/MinGW and Cygwin Pythons are **not** supported:
  `paddlepaddle` and `llama-cpp-python` do not publish wheels for them.
- **paddlepaddle** is the CPU build from PyPI — do **not** install
  `paddlepaddle-gpu`.
- **llama-cpp-python** installs from the prebuilt CPU wheel index that
  `requirements.txt` points pip at
  (`--extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu`). If
  no matching wheel exists for your platform/Python and pip falls back to
  building from source, you need a C/C++ compiler and CMake (see per-platform
  notes below), then reinstall.
- On first run, PaddleOCR downloads its detection and recognition models to
  `~/.paddlex/` (needs internet once).
- **Tesseract** is a separate program, not a pip package (`pytesseract` only
  calls it). Install Tesseract 5 (includes English); the code finds it on PATH,
  or set `TESSERACT_CMD` to the full path of the `tesseract` binary.

### Windows

- Activate the venv with `.venv\Scripts\Activate.ps1`. PowerShell may block it;
  fix with `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
- A `win_amd64` llama-cpp-python wheel is installed, so nothing is compiled. If
  you need a source build, install *Visual Studio Build Tools* with the
  "Desktop development with C++" workload plus CMake.
- **PaddleOCR on Windows CPU:** the pipeline creates PaddleOCR with
  `enable_mkldnn=False`, which avoids a oneDNN crash in Paddle 3.x on Windows
  (harmless on other platforms).
- **Tesseract:** `winget install --id UB-Mannheim.TesseractOCR -e` (tested
  5.4.0). The installer does not add it to PATH; the code finds it in
  `C:\Program Files\Tesseract-OCR\` automatically.

### Linux

- Activate the venv with `source .venv/bin/activate`.
- If llama-cpp-python builds from source, install a compiler + CMake first:
  `sudo apt install build-essential cmake` (Debian/Ubuntu) or the equivalent
  (`gcc-c++`, `cmake`) on Fedora/Arch.
- **Tesseract:** `sudo apt install tesseract-ocr` (Debian/Ubuntu) or
  `sudo dnf install tesseract` (Fedora). It lands on PATH, so no `TESSERACT_CMD`
  is needed.

### macOS

- Activate the venv with `source .venv/bin/activate`.
- Install the command-line build tools once (`xcode-select --install`), and
  `brew install cmake`, in case llama-cpp-python builds from source.
- **Tesseract:** `brew install tesseract`.
- **Apple Silicon (arm64) caveat:** `paddlepaddle` / PaddleOCR CPU support on
  arm64 macOS is limited and may not install cleanly. If it fails, use an
  x86_64 Python under Rosetta, or run the Tesseract engine and the LLM/VLM
  stages (which do install on arm64) and skip PaddleOCR. This path is untested.

## Download the model

Phi-3-mini-4k-instruct, Q4 GGUF (~2.2 GB), into the gitignored `models/` folder:

```bash
mkdir models
curl -L -o models/Phi-3-mini-4k-instruct-q4.gguf \
  https://huggingface.co/microsoft/Phi-3-mini-4k-instruct-gguf/resolve/main/Phi-3-mini-4k-instruct-q4.gguf
```

The other models used in the comparison (optional) are Qwen2.5-3B-Instruct and
Llama-3.2-3B-Instruct, Q4_K_M GGUF, also placed in `models/`. See
[usage.md](usage.md#extraction-stage) for the registry names.

## Check the environment

```bash
python scripts/check_env.py
```

The script imports all core libraries, OCRs one SROIE receipt with both OCR
engines, runs one short generation with the GGUF model and prints timings. It
ends with `[OK] environment check passed`. Datasets go under
`evaluation/datasets/<name>/raw/` (see
[../evaluation/datasets/README.md](../evaluation/datasets/README.md)). Raw data
and model files are gitignored.

## Run the tests

```bash
python -m pytest tests -q                  # full environment
pip install -r requirements-test.txt       # or: minimal environment for tests only
```

The tests need **no PaddleOCR, llama-cpp, Tesseract, dataset or model files**.
The minimal environment is just pytest, pydantic, pillow, pyarrow and numpy,
and the suite runs in a few seconds.

- **Fixtures:** tiny synthetic fixtures in `tests/fixtures/` stand in for the
  data. They're generated by `tests/fixtures/make_fixtures.py` and reproduce
  real quirks: Windows numbered copies, missing and empty labels, duplicate
  images with conflicting labels, rupiah totals, derailed and prose LLM
  outputs.
- **Stand-ins:** OCR engines and the LLM are replaced by stand-ins.
- **Import check:** a test checks that importing the project never loads the
  OCR or LLM libraries.
- **CI:** GitHub Actions (`.github/workflows/tests.yml`) runs the suite on
  Ubuntu and Windows for every push to `main` and every pull request.

See [testing.md](testing.md) for the full test plan and coverage.
