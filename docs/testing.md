# Testing

The test suite is built around one rule: **it must run with no PaddleOCR,
no llama-cpp, no Tesseract, and no model or dataset files** — so it runs in a
few seconds, on CI, and on a fresh clone. The heavy, non-deterministic parts
(real OCR and model inference) are tested at a separate level that is skipped
when the models aren't present.

## Test levels

| Level | What it checks | How | Runs in CI? |
|---|---|---|---|
| **Unit / logic** | Pure functions: normalisation, lenient JSON parsing, the schema, reading-order layout, evaluation scoring, failure tagging, the UI service helpers | direct calls | ✅ |
| **Component (with fakes)** | The wrappers around the heavy libraries — OCR result conversion, the llama-cpp wrapper, model-registry resolution — using a **fake OCR engine** and **fake LLM** | stand-ins injected | ✅ |
| **Smoke / integration (fixtures)** | The whole pipeline wired together: fixture manifest → `run()` (fake OCR + LLM) → run log → `evaluate()` | synthetic fixtures | ✅ |
| **Real-stack integration** | The actual model load + inference path (`tests/test_integration.py`) | loads a real GGUF, runs one generation | ⏭️ skipped unless models present |
| **Environment check** | The real OCR engines and the GGUF model load and produce output end to end | `scripts/check_env.py` | ▶️ run manually |

The import-guard test asserts that importing the project never pulls in
`paddleocr`, `paddle`, `paddlex`, `llama_cpp` or `pytesseract`, which is what
keeps the fast suite dependency-free.

## Running the tests

```bash
python -m pytest tests -q                      # full (uses the project venv)
pip install -r requirements-test.txt           # or the minimal env: pytest, pytest-cov, pydantic, pillow, pyarrow, numpy
python -m pytest tests -q                       #   then the same command

python -m pytest tests -q -m "not integration"  # skip the real-stack test explicitly
python -m pytest tests/test_integration.py       # real-stack test (needs models/ + llama-cpp)

python -m pytest tests --cov --cov-report=term-missing   # coverage (config in .coveragerc)
```

The **real-stack integration test is marked `integration` and auto-skips** when
the GGUF model or `llama_cpp` is absent, so CI and a fresh clone skip it; run it
locally with the models in `models/` to cover the real load + inference path.

## Fixtures

Tiny **synthetic** fixtures in `tests/fixtures/` (generated by
`make_fixtures.py`, committed so they can be rebuilt) stand in for the data and
reproduce real quirks seen in the datasets: Windows numbered copies, missing and
empty labels, duplicate images with conflicting labels, rupiah totals
(`Rp 60.000`, `35.000,00`), single-item vs list menus, and fenced / derailed /
prose LLM outputs with empty OCR. No real receipts are committed, so there is no
licence issue.

## Coverage

Measured over `src/`, `evaluation/` and `app/` (config in `.coveragerc`).

**Snapshot (2026-10-28): 169 fast tests, 69% overall.**

| Area | Coverage | Notes |
|---|---|---|
| Core logic — schema, prompts, layout, `__init__` | 100% | pure functions |
| base / normalize / parse / runlog | 91–98% | pure functions |
| evaluation (`evaluate.py`) | 88% | scoring; CLI `main()` excluded |
| failure tagging (`tag.py`) | 81% | rules + counts + review sampling |
| UI service (`app/service.py`) | 78% | logic; model-loading lines excluded |
| real inference — `llm.py` / `paddle.py` / `tesseract.py` / `vlm.py` | 51–84% | load + inference lines; see below |
| analysis scripts — `show_case.py` / `make_review_v1.py` / `by_model.py` | 22–48% | pure helpers tested; display/`main` not |

What is **deliberately not** covered by the fast suite, and why (documented, not
hidden — see the header of `.coveragerc`):

- **Real model loading and inference** (the `Llama(...)` call, `_predict` on the
  OCR engines, the VLM generate). These need the ~10 GB of gitignored models and
  the heavy libraries, and a single call is seconds-to-minutes — unfit for a
  fast suite, and the load line itself carries no project logic. The logic
  *around* them is tested with fakes; the real path is covered by the **gated
  integration test** when it can run, plus `scripts/check_env.py`.
- **`app/app.py`** — the Streamlit *render* layer. All its logic lives in
  `app/service.py` (which is measured); the rendering is checked with a manual
  headless boot. Omitted from coverage.
- **CLI `main()` / `__main__` entry points** — thin argparse wrappers over the
  functions that the suite already tests.
- **The interactive analysis scripts** (`show_case.py`, etc.) — their pure
  helpers (`squash`, `find`, `spread`, `counts_by_cell`, …) are unit-tested; the
  terminal-display functions are exercised by hand during the taxonomy review.

So the headline 69% is dominated by code that is tested at a different level or
is pure presentation: the **pure logic the thesis depends on is covered at
78–100%**.

## Continuous integration

GitHub Actions (`.github/workflows/tests.yml`) runs the fast suite on **Ubuntu
and Windows**, Python 3.12, for every push to `main` and every pull request. The
integration test auto-skips there (no models), and the dependency-free design
means CI needs only the minimal test requirements.
